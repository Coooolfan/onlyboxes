# BoxLite 原生归档与恢复

Worker 固定依赖 BoxLite `0.10.7`，使用原生 `.boxlite` 归档验证同 runtime 的文件系统恢复。Worker 通过[显式生产配置](sandbox-snapshot-deployment.md)注册 `sandbox_persistence` 能力，原生管理帧适配覆盖源端快照和回滚、目标恢复和激活，以及撤销和永久删除。启动配置绑定独立 lease 守护器和专用 home；未知结果、异常宿主恢复及跨机器验收仍待完成。

## 原生验收

```bash
cargo run --locked --example boxlite_snapshot_smoke
```

需要可运行 BoxLite 的本机环境、`protoc >= 3.12` 和可访问的镜像 registry。默认镜像使用固定 digest，包含 `/bin/sh` 与 Python。可通过 `BOXLITE_SNAPSHOT_SMOKE_IMAGE` 指定另一个带 digest 的 Debian/Python 镜像；样本会删除 guest 内的 `/etc/debian_version` 以验证基础镜像文件的删除行为。

验收只创建并删除本次调用拥有的临时目录和原生 Box：

1. 子进程在独立 source home 创建并启动 Box，写入文件与元数据样本。
2. 调用 `stop()`，核对状态为 `Stopped`，保留原生实例并导出归档。
3. 源进程使用临时授权向本次测试的 HTTP 对象服务分片上传。父进程校验分片应答并完成对象，再由独立子进程完整 GET 回读与 SHA-256 校验。
4. 父进程删除整个 source home、所有源 journal 和本地源归档，包括源数据库、镜像缓存、backing 文件和 Box 目录。
5. 另一子进程只通过 HTTP 下载共享归档，完整校验后在全新的 target home 规范化并导入，核对导入本身不启动实例、目标原生 ID 与源不同。
6. 显式启动目标，验证文件系统与启动配置，记录示例中的本地激活后再次挂起、导出并校验，最后删除目标和测试目录。失败时保留本次测试目录用于排查。

验收失败会返回非零退出码。输出包含归档字节数、SHA-256、导出和导入耗时。

2026-10-18 在 macOS/arm64 上直接调用 BoxLite 0.10.7 原生 SDK 的小样本结果（不包含平台归档规范化、额外校验和重试）：

## 生命周期接入约束

`WORKER_TERMINAL_EXEC_BOXLITE_DISK_SIZE_GB` 为新 terminal Box 选择稀疏根盘容量；SDK 按 GiB 计量并保留至少基础镜像大小。默认未指定容量时，guest 根文件系统可能不足 1 GiB，即使宿主有充足空间，大文件也会收到 `ENOSPC`。容量随私有 `RestoreSpec.disk_size_gb` 保存并参与归档校验和缓存匹配，恢复按原规格创建；目标 Worker 的新默认值不能改变已有快照的容量。[配置说明](config-file.md)列出范围和未完成的默认值变更验收。

2026-10-25 在 macOS arm64、BoxLite 0.10.7、真实 Console/MinIO 和两个独立 Worker 上，以 debug 构建、4 GiB 根盘完成 1 GiB 随机数据的跨 Worker 验收。配置归档上限 2 GiB、展开上限 8 GiB，开始前检查主机与存储 daemon 至少有 28 GiB 空闲空间。提交归档为 1,112,872,949 字节，17 个持久化分段回执覆盖全部归档。挂起观察耗时 271.02 秒、恢复观察耗时 367.61 秒；源、目标 journal 中容量均为 4 GiB。完整文件哈希、权限、符号链接和最终清理通过，积压归零。[脱敏样本](sandbox-snapshot-s3-sample-2026-10-25.json)保存实际展开量、规格与计时条件。

这是一条新建会话的单次本机链路，采用约一秒操作轮询，未拆分原生处理、上传、回读和下载阶段；不代表跨物理机器、冷缓存、并发、百分位或生产延迟承诺。初始会话失败后的遗留根盘协调和默认容量变更另见配置中的验收边界。

2026-10-25 的另一轮本机真实 Console/MinIO 验收使用 release 构建、8 GiB 根盘和 5 GiB 随机数据。第一次挂起因 12 GiB 展开预算不足返回 `snapshot_quota_exceeded`，原实例回滚后完整文件哈希仍匹配；提高到 16 GiB 后，复用同一会话和原生 ID 完成跨 Worker 恢复。归档 5,408,235,879 字节、展开量 14,097,711,104 字节，81 个分段回执覆盖全部归档；挂起观察耗时 77.50 秒、恢复 94.66 秒。源、目标保存的规格一致，容量均为 8 GiB。完整哈希、权限、符号链接、源重新上线与永久删除通过，清理积压为零，两侧均无剩余 guest qcow 磁盘。[脱敏样本](sandbox-snapshot-s3-release-5g-sample-2026-10-25.json)记录预算拒绝、重试条件、暂存预留和局部盘占用采样。

磁盘采样从认证/创建 payload 前持续到校验、删除、清理及客户端退出。跨 Worker 覆盖 55.80 秒、82 个样本，同 Worker 覆盖 50.03 秒、74 个样本；最大实际采样间隔分别约 0.753 和 0.724 秒。两次 SDK home/journal 的按 inode 分配字节计量基线约 0.88 GB，观察峰值分别为 5,452,726,272 与 5,454,049,280 字节，完整曲线见样本。计量包含已有镜像缓存及 journal 历史，排除对象存储与构建产物；不遍历符号链接、对硬链接去重，COW/reflink 共享物理块仍可能重复计量，短暂峰值可能漏采。采样开销未扣除，不能将此计量当作精确物理峰值或据此缩减暂存预留。受控冷/热镜像、多次重复、5/10 GiB 及更大并发的阶段曲线和跨机器测量仍需补齐。

原生 export 会在磁盘复制期间 quiesce，但复制结束会恢复运行中的源实例。平台挂起必须先关闭命令和预览入口、排空执行，再停止所有写入；不能把直接对运行中 Box 调用 `export()` 视为已挂起。当前验收使用停止后的导出，不保留进程或内存。

归档可以在空 home 导入，但目标启动仍需要访问基础镜像 registry。恢复规格必须使用固定平台 digest；不能将可变 tag 的一次成功恢复当作基础镜像一致性的证明。

SDK 的 `BoxArchive::new` 采用可信本地归档策略，会保留归档携带的启动与安全配置。平台适配器必须在导入前核对受控恢复规格、路径和挂载边界、完整 SHA-256、大小及展开预算，再决定导入策略。原生 SDK 的校验不能代替 Console 的账号归属、generation、所有权和激活栅栏。

原生管理帧引擎已连接 journal、执行门禁、直接对象传输、目标容量预留、显式激活与删除原语。显式生产配置接入启动前 home/lease-store 核对、独立执行租约和周期缓存清扫后才声明恢复能力；异常宿主与未知启动结果协调、未登记孤儿和跨物理机器验收仍需完成。当前生产配置与验收边界见[部署说明](sandbox-snapshot-deployment.md)。

## 持久化 journal

`worker_boxlite::persistence` 提供 BoxLite Worker 的私有恢复规格、归档描述与操作 journal。会话管理器及生产启动路径安装同一 journal、执行门禁与恢复握手，原生生命周期控制器处理 Console 管理帧。单独 journal 测试不代替真实 Console/S3 或跨机器验收。

journal 目录使用独立绝对路径，按 Worker identity 绑定。目录及 artifacts 子目录必须属于当前用户且仅当前用户可访问，文件必须为私有普通文件、单硬链接。进程独占锁覆盖 journal 句柄的整个有效期；相同目录不能同时被另一个进程或句柄打开。显式 close 先解锁再关闭描述符，并使原句柄失效；并发 fork 在 exec 前短暂继承的描述符不能延迟这次所有权释放，旧描述符随后关闭也不能解除新所有者的锁。符号链接、FIFO、异常权限、损坏 JSON、未知字段和超限文件都会拒绝加载。

每次变更先复制并验证完整状态，再写入权限为 `600` 的临时文件，执行文件 sync、原子 rename 和父目录 sync，之后才返回成功。写入出错会禁用该句柄的读取与后续操作；即使 rename 实际已经完成、仅应答丢失，也必须重新打开 journal 核对状态，不能使用旧内存状态继续执行。独立 owner 标记用于识别 journal 丢失，禁止将已有目录自动重置为 generation 1。若整个状态目录被删除，后续启动集成仍需核对原生资源，不能仅凭新目录为空判断不存在旧实例。

操作记录保留账号作用域 session、generation、操作种类和阶段、固定镜像与资源规格、原生 Box ID、归档身份与校验确认。环境变量和启动命令属于私有规格，不实现 `Debug` 输出。传输授权和签名 URL 没有持久化字段，不能作为额外 JSON 字段写入记录。

磁盘 journal v2 使用[按 SHA-256 共享的规格表](sandbox-snapshot-journal.md)，减少重复私有配置写入，读取时先验证引用及展开预算，再恢复完整逻辑视图。Worker 可读 v1/v2，后续成功变更写入 v2；旧 Worker 拒绝 v2。全部操作和原生回收凭据继续保留，未决结果不能因共享编码而被认定为已清理。

主要约束：

- 同一操作的重试读取原阶段，不能重新选取归档、规格或原生实例。
- 初始探测固定已有 Box ID；同名替代实例不能被当作原实例采纳。
- source 提交需要归档已校验且远端完整回读已确认；恢复点提交后才能进入源清理完成阶段。
- target 导入需要本地归档已校验，ready/active 必须具有原生 Box ID 与绝对 lease；lease 只能延长。
- 同一 session 的并发 target 认领只能成功一个；取消、终态和 generation 检查限制旧请求的重放。
- 删除记录永久阻止同一稳定 session 的恢复与重建，更高 generation 的未知取消也不能取代删除栅栏。
- 归档文件名由 session、操作与 generation 的摘要生成，不将这些值直接拼接为本地路径。

`cargo test --locked --lib` 覆盖状态机、不可变身份、损坏与私有文件检查、并发认领、真实跨进程锁、子进程被强制结束后的记录恢复，以及写入失败和丢失提交应答的处理。该测试不创建 VM，也不验证对象存储或 Console 协议。


## 原生实例检查与停止写入

`persistence::NativeRuntime` 提供不启动实例的只读检查，以及 journal 约束下的源实例停止原语。Worker 的确定性 session 名称与检查器复用同一个名称生成函数，避免运行路径与持久化路径对实例归属产生不同解释。

检查器要求 BoxLite home 为当前用户拥有、权限为 `700` 的独立绝对路径，不自动修改权限。它按调用方已持有的不可变 Box ID 查找实例，核对账号作用域名称、原生资源与实际镜像解析记录；不按名称寻找替代实例，不从当前 Worker 配置推测已有实例的启动规格。

BoxLite 0.10.7 的公开 `BoxInfo` 不提供完整启动配置。检查器使用只读 SQLite 连接，在同一读取事务内核对 SDK 数据库 schema 10、唯一名称索引与配置 JSON 的一致性，以及该 Box 的不可变 `BoxConfig`。数据库读取有大小上限，不执行迁移或写入；数据库、Box 目录和配置中的 home 不能通过链接跳转到其他位置。SDK 升级必须同步核对该读取契约并运行原生验收。

支持的恢复规格限定为 Libkrun、当前 guest 架构、固定镜像 digest、CPU/内存/进程数，以及可表达的用户、工作目录、环境变量和启动命令。实际镜像 digest 来自原生解析记录，原始可变 tag 不作为恢复身份。其余选项必须匹配 Worker 的已知安全配置；挂载、自定义内核、其他 VMM、自动删除、主机端口、特权模式、自定义宿主隔离配置及未知选项都会拒绝采纳，避免导入时丢失约束或引入宿主依赖。

`stop_source` 要求当前 journal 已认领同一个 source 操作、generation、原生 Box ID 与完整规格。调用方必须先关闭命令/预览入口并排空执行。停止确认前后均检查实例和 journal，停止不确定时保持原记录用于重试；不会删除源实例或创建替代实例。重复停止保持同一个 Box ID。停止后的源磁盘仍应保留到共享归档提交与回读确认完成。

原生归档 smoke 会验证只读检查不停止 VM、未认领及规格不匹配的操作不能停止 VM，以及正确认领后的幂等停止。之后继续执行原生导出和空 home 恢复。这是独立的运行时验收：测试删除 source home 的步骤不表示生产协议可以在共享存储提交前删除源数据。

停止前先读取当前原生实例的私有 `shim.pid`，要求 SDK PID、PID 文件中的启动时间与操作系统观察一致，再把稳定宿主身份、本次宿主启动 UUID、PID namespace、PID 和进程启动时间持久化为不可换绑的 `source_process`。PID 文件缺失、旧格式、损坏、链接或身份冲突都会保留源实例并报错，不把读取失败当作进程不存在。

SDK 在无法附着 live state 时仍可能继续清理并记录停止，因此 `Stopped` 元数据本身不足以确认停止。SDK 停止后还会等待最多 10 秒，独立核对原进程及其写入者已退出，再持久化不可撤销的 `source_stop_confirmed`。原进程仍活着或操作系统证据不可读时不能进入 `frozen`；停止前未记录进程身份的已停止实例也不能直接采纳。进程查询不会发送终止信号或回收其他进程；同宿主重启可证明旧启动中的全部写入者结束，PID 启动时间变化只证明该 PID 的旧生命周期结束。宿主身份不同，或同一次宿主启动内 PID namespace 改变，则拒绝确认，不能把 journal 跨机复制或 PID 不再可见当作原进程已退出。

Linux detached 模式的 SDK PID 可能只是外层 launcher，其退出后内层 PID namespace 中的 VM 仍可存活。SDK 的整组清理属于 best-effort，不能代替停止证明。适配器在进程仍运行时读取精确 `/proc/<pid>/cgroup`，要求统一 cgroup v2、路径末尾与 `boxlite/<Box ID>` 匹配、真实 cgroup2 文件系统，并把目录设备号和 inode 随进程身份固定到 journal。PID 身份随后再次核对，防止采集期间换绑。停止、已冻结导出重放、回滚和删除/残留清理都要求旧 PID 退出，且原 cgroup 的分层 `cgroup.events` 为 `populated 0`，包括所有后代。事件通过固定目录描述符读取；同名替换、缺失组、损坏事件或权限失败都保持不可用。旧的仅 PID 记录在同一次 Linux 启动内不能作为完整写入者退出证明，也不会通过补写一个空组来修复。

源操作的冻结、提交和完成记录必须包含停止确认与原进程身份。Worker 在 SDK 已停止、停止确认尚未写入时退出，重开 journal 后仍可用原身份补齐确认，不依赖 SDK 可能已经删除的 PID 文件。已冻结归档重放也要求这项身份记录和退出证据。未确认的停止保留原实例、磁盘和操作记录，由生命周期恢复流程继续核对。

这些原语要求本地 SDK home 与 journal 由同一宿主独占，不共享或复制到另一台宿主运行。Linux 需要宿主唯一且可读的 `/etc/machine-id`、`/proc/sys/kernel/random/boot_id` 、`/proc/self/ns/pid` 及进程启动时间；容器部署须提供正确的宿主身份，不能使用预烘焙的重复 machine-id。macOS 使用 `gethostuuid`、`kern.bootsessionuuid` 和内核进程启动时间。身份读取不可用时停止原语报错。持久化启动在 SDK 初始化与恢复前检查宿主、namespace、本地 home/journal 和外部 lease store 归属；独立守护器持续执行到期停止。异常宿主和未知启动结果保持关闭并等待明确协调。

[Linux 写入者测试](../tests/linux-writer-evidence/README.md)直接编译生产 cgroup 模块，不链接 VM SDK。本机 Linux/arm64 容器已验证 launcher 被杀死并回收后，活跃后代仍会阻止退出确认；整组停止后才确认空组，同时拒绝 inode 变化、缺失或重建的同名组。该测试未启动真实 Linux BoxLite VM，不代替 SDK 放置、独立 execution lease 或跨机器验收。

进程退出查询也识别尚未被父进程回收的僵尸状态。Linux 从 `/proc/<pid>/stat` 同次读取状态与启动时间；macOS 通过 `PROC_PIDTBSDINFO` 的包含僵尸查询读取状态和启动时间，只有内核明确返回僵尸状态才作为该 PID 已结束的证据。[XNU 的进程信息实现](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/proc_info.c)定义了这项查询。读取失败、权限错误或单纯 PID 文件缺失仍不是退出证据；Linux 仍额外要求原 cgroup 的全部后代为空。

### 独立停止原语

`NativeRuntime::inspect_writer` 对原终端的 scope、固定 Box ID、名称、规格、运行状态和 PID 进行两次核对，返回可持久化的写入者身份；它不启动或停止实例。`HostProcess::request_writer_stop` 可在没有 SDK runtime 的独立进程中对该身份请求强制停止，保留 guest 磁盘和 SDK 数据库。返回成功只表示停止请求已交给内核，调用方仍须通过 `writers_exited` 确认写入者退出，不能把信号投递当作清理完成。

Linux 使用已固定设备号和 inode 的 cgroup 目录描述符打开 `cgroup.kill`，只终止该组及其后代，不向单个可复用 PID 发信号。macOS 在 PID 与启动时间核对期间，通过 task-name right 读取 audit token 的 PID version，仅持久化版本号；停止时使用 `proc_signal_with_audittoken`，让内核在投递 `SIGKILL` 时校验 PID 和版本，避免用户态先检查再 `kill(pid)` 的复用窗口。缺少版本、跨宿主/namespace、内核接口不可用或 cgroup 被替换时均拒绝，不降级为普通 PID 信号。[Apple 的 audit-token 信号接口](https://github.com/apple-oss-distributions/xnu/blob/main/libsyscall/wrappers/libproc/libproc.c)、[内核的 audit-token 信号处理](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/proc_info.c)给出了对应的系统接口和校验路径。

macOS 单元测试验证错误版本无法停止仍活着的自有子进程，精确版本可停止，缺少版本及跨宿主/namespace 会拒绝。原生 `boxlite_home_guard_smoke` 由未初始化 SDK 的独立守护子进程执行租约；SDK 宿主被 SIGKILL 后，同一 VM 继续通过重连、后台写入和 orphan 保留检查，随后在续租期限到期时停止，确认进程退出及 guest 磁盘仍在，再由 SDK 完成授权删除。Linux 内核测试直接使用同一 cgroup 停止实现，覆盖后代退出和 inode 不匹配拒绝。

这些原语供[持久租约账本与到期执行](execution-lease.md)使用，原生实验已有独立子进程的续租与到期停止。生产私有控制协议、启动、采纳、受控启动前授权、续租和普通重连接入同一个外部监督的守护器；异常宿主与未知结果仍需明确协调。

原生 smoke 验证正常退出的进程证据、SDK 停止后丢失确认的重试，以及无先前进程证据时拒绝采纳停止状态。无 VM 测试使用真实子进程验证 Worker 被 SIGKILL 后仍保留身份、活跃写入者不能确认停止、退出后才能冻结，以及确认不可撤销。它不等同于在真实 SDK 无法附着且 shim 仍活着的分支注入故障。另在 Linux/arm64 的临时 Rust 容器中复用同一进程身份模块源码和固定 SDK 的进程查询实现，进程身份测试通过；容器提供独立的测试 machine-id，当前可通过 Linux 写入者证据 harness 复验。这只验证 Linux 内核查询与身份判断分支，不验证 Linux 上的 BoxLite VM 或完整 Worker 生命周期。

原生操作由生命周期控制器接入 Worker 管理帧，`sandbox_persistence` 声明需显式配置和归属检查通过。[session 门禁](sandbox-snapshot-session-gates.md)已有 generation、控制连接、source 保留和 ready 绑定的检查与入口。归档处理原语已实现固定镜像、规格、字节上限和完整性校验；运行中的 Worker 已接入全局暂存预留、传输编排、显式激活、恢复握手及已授权回收；未登记孤儿巡检、账本维护和完整跨机器验收仍待完成。


## 受控导出与归档校验

`NativeRuntime::export_source` 从 journal 中已认领的 source 操作导出。停止前先确认 guest `os.sync()` 成功；刷新失败会保留原实例与操作记录用于核对。导出、压缩和完整校验在阻塞任务中运行。源实例及原始磁盘不会因成功导出或校验失败而删除。

导出先写入按操作标识隔离的私有工作目录，再验证和规范化原生归档。规范化只改变 manifest 与 tar 表达，磁盘逻辑字节及其 SHA-256 保持一致；镜像引用由原始 tag/index 改为已核实的平台 digest。完成后按不可覆盖方式发布归档、sync 父目录，最后将 journal 更新为 `frozen`，记录完整归档 SHA-256、大小和 `verified`。这不等于共享存储已经提交，`remote_verified` 与 `snapshot_committed` 不会由导出设置。

重复请求会完整校验并复用已选归档。若发布文件后、journal 应答前中断，重试会核对同一个私有归档并补齐记录，不能覆盖或重新选择另一组字节。

校验边界：

- 仅接受当前原生 v3 manifest、zstd tar、`manifest.json` 与 `disk.qcow2` 两个成员。
- manifest 不超过 64 KiB，字段与启动规格必须受支持且匹配；未知选项和重复成员会拒绝。
- 路径穿越、额外文件、链接、目录、FIFO、PAX 与长路径扩展会拒绝，不将成员解包到宿主路径。
- GNU 稀疏磁盘支持流式读取；稀疏扩展最多 1024 个头，预检发生在 tar 逻辑读取器分配块表之前。
- QCOW2 必须为支持的独立磁盘头格式，不允许 backing 引用、外部数据文件、加密或不兼容标记；同时检查完整磁盘 checksum。
- 原始归档、规范化输出和传入的恢复归档均有字节上限，并核对完整归档 SHA-256。输入与输出不能是同一个 inode。
- 展开预算保守计入 QCOW2 文件逻辑长度、虚拟容量及 64 KiB manifest 余量；压缩大小不能代替这个预算。

`prepare_import_archive` 先验证已提交归档的描述、完整 SHA-256、账号作用域与恢复规格，再生成本机私有导入归档。归档只可携带已知 Linux/macOS 默认宿主安全配置，导入前统一重建为当前机器的默认隔离与受控资源限制。调用 SDK 的可信本地导入策略之前必须完成这一步，不能直接沿用源机器的宿主配置。

SDK 不会为导入实例补齐 `resolved_image`。`inspect_target` 因此要求 journal 中存在当前 target 操作、已验证归档、已选择的不可变 Box ID 和固定规格，并核对原生配置中的完整 digest 与该规格一致。普通源实例采纳仍要求原生镜像解析记录，不能使用这条导入专用路径采纳任意已有实例。

当前 `cargo run --locked --example boxlite_snapshot_smoke` 覆盖规范化导出、冻结记录重试、发布后未收到 journal 完成应答的恢复、预算拒绝后源数据保留，以及删除源 home 和源 journal 后的目标导入与完整规格核对。样本代码写入文件后不自行执行 sync，由停止原语负责刷新。目标恢复仍验证内容、链接、权限、UID/GID、FIFO、xattr、稀疏文件、基础镜像文件删除、环境变量和 tmpfs 排除。

这条校验流程比裸 SDK 增加完整读取与压缩。一次 debug 构建的小样本中，含冻结归档重放校验的源流程约 25 秒，目标规范化与导入约 24 秒，归档约 38.8 MB、展开预算约 924.5 MB；这些时间不是 release 性能或容量验收结果，也不包括共享对象传输。已有上文 1 GiB debug 和 5 GiB release 的本机 Console/S3 单并发样本；10 GiB、并发及受控冷/热缓存性能矩阵仍需单独完成。

生命周期控制器仍需在调用前预留 SDK home 与 journal artifacts 两处空间，管理在途任务、缓存和临时文件。SDK 原始导出使用其原生暂存机制，原始归档大小在导出完成后检查；这里的限制不能代替文件系统配额或节点级磁盘准入。取消时必须跟踪并等待 SDK 已启动的原生 I/O，不能仅丢弃 Future 就释放占用。崩溃遗留工作目录和 SDK 临时文件的巡检回收仍待接入。

原生导入使用下述 journal 约束的导入原语；删除栅栏、实例/路由激活与运行中 Worker 的恢复握手仍需控制器落实。

已导入实例再次挂起时，`inspect_source` 会要求同一 scope、generation、Box ID 与完整规格对应的已激活 target 记录，才能使用导入时固定的镜像身份。原生验收覆盖导入、记录本地激活后再次导出；它仍不验证 Console 激活事务。journal 回收必须保留当前原生实例依赖的这条导入证据，不能把它作为无引用历史记录删除。


## 受控导入与实例身份

`NativeRuntime::import_target` 从当前 target 操作及其固定 artifact 读取已下载归档，完整核对 SHA-256、范围、规格与展开预算，并生成当前主机安全配置下的私有导入归档。SDK 导入前先持久化 `verified` 与 `importing`，导入后验证停止状态和完整规格，再持久化不可变 Box ID。该原语不会启动实例或开放命令/预览入口。调用方须先预留 SDK home 与 journal 两处暂存空间、按 session 串行执行，并在取消后继续跟踪 SDK I/O 至结束。

普通新建会话沿用 `onlyboxes-terminal-v1-<scope 摘要>` 名称。恢复实例使用 `onlyboxes-restore-v1-<scope、operation、generation 元组摘要>`；SDK 数据库的名称唯一约束使不同恢复代次拥有独立名称。名称不包含账号、session 或操作的明文。Worker 管理器后续必须使用已记录的原生 ID 绑定恢复实例，不能通过普通创建路径重新寻找稳定名称。

若 SDK 已导入但 journal 尚未记下原生 ID，重试仅检查本次操作的完整派生名称，要求实例仍停止、完整启动配置一致，且本机独立 `disk.qcow2` 的逻辑长度与完整 SHA-256 均等于已验证归档中的磁盘。随后才能将该 ID 固定到当前操作。运行中的未知候选、其他代次名称、内容改变的磁盘或配置冲突都会拒绝采纳；不以名称与镜像相同作为充分依据，不创建空白替代实例。

已有 Box ID 后，重试按同一个 ID 核对，实例缺失会报告缺失，不能重新导入并换 ID。若该实例已经运行，还要求 journal 中的绝对 lease 尚未过期；导入原语不续期，也不替代独立 lease 强制执行。后续控制器仍须在启动之前持久化 lease，待环境就绪后保持入口关闭，完成 Console 所有权提交与激活握手。

恢复实例再次挂起时，检查器从同一 generation、Box ID 与规格的已激活 target 记录取得原生操作名称。导出先核对实际名称，再把归档 manifest 规范化为稳定的 scope 名称；下一次恢复不依赖前一 Worker 的操作名称或本机 ID。归档磁盘字节不因名称规范化而改变。

原生 smoke 覆盖旧稳定名称仍存在时的新导入、同 journal 重试，以及根据重建的导入中间记录找回同一个停止实例。预算不足、取消、删除记录取代旧操作及错误 generation 均不能创建或采纳目标；已选原生实例被移除后，重试报告缺失，不会创建替代实例。重建记录模拟“SDK 已完成、原生 ID 应答未记入 journal”的状态，不等同于在 SDK 导入任意指令处执行强制退出。名称隔离、原生磁盘完整性及链接拒绝另有无 VM 测试。示例的 `import_ms` 计入下载、归档规范化、磁盘核对和应答丢失重放，不是单次裸 SDK 导入延迟。定期孤儿扫描与 Worker 生产启动恢复仍需接入。


## 直接对象传输

`persistence::Transfer` 使用仅存在内存中的 `TransferGrant`，支持上传分片、完成对象后的完整 GET 回读、断点下载与已验证的本机归档复用。授权 URL 和 headers 不写入 journal、下载标记或公开错误；续期和分片完成仍由 Console 协议编排，Worker 不持有 S3 主凭据。

传输与阻塞文件 I/O 分别共享 1–16 个并发配额。流式读写以 64 KiB 块处理，上传按固定 FD 的独立偏移读取，先完整校验 SHA-256，再核对每批上传前后的 inode、长度和修改时间。单批最多 16 个分片，重复编号、重叠范围和越界范围在发起请求前拒绝。分片应答要求 HTTP 200 和 ETag；ETag 不能代替最终完整 GET 的大小与 SHA-256 校验。

授权过期、主动取消、连接失败或 1–600 秒无进度超时会终止请求；超时覆盖等待响应头、传输正文与等待上传确认。等待并发配额时同样检查授权过期和取消。禁止 HTTP 重定向和透明内容解压，校验授权 method、Host、Content-Length 和 headers，不透传远端错误正文。已经启动的阻塞 I/O 在实际返回前继续占用文件配额；取消 Future 不会提前释放这项配额。

下载目标必须位于当前用户拥有的私有目录。每个目标使用跨进程排他锁，`.partial.json` 只持久化固定归档描述，`.partial` 不能被另一 snapshot 继续使用。短读、网络失败或取消保留私有前缀；重试的 HTTP 206 必须精确匹配剩余 Content-Range，服务端返回完整 HTTP 200 时从零开始。错误范围、长度或完整 checksum 会丢弃本次对应的临时文件。完整校验和文件 sync 完成后才能通过不可覆盖的 hard link 发布，并 sync 父目录；发布后丢失应答可以根据同 inode 恢复。已发布缓存每次复用都完整核对大小和 SHA-256，损坏缓存由调用方决定清理，不直接覆盖。

原生 smoke 使用临时 HTTP 对象服务验证“导出 → 分片上传 → 协调方完成对象 → 完整回读 → 删除源状态 → HTTP 下载 → 空 home 导入 → 再次挂起”。该服务使用测试授权，不实现 S3 签名、版本控制、条件 manifest 写入或 Console 事务，不能作为真实 S3 兼容性或跨机器验收。传输故障测试覆盖中断续传、取消、响应头/正文停滞、授权过期、错误范围、checksum 失败、重定向、文件替换、发布应答丢失和阻塞 I/O 配额保持。

这些是传输原语。Worker 的持久化能力声明、Console 授权续期与回读确认、缓存配额及回收仍需生命周期控制器接入。

## 受控启动与 source 回滚

`NativeRuntime::start_target` 只启动当前已验证、固定 Box ID 的 target；`rollback_source` 只恢复尚未提交的原 source，保留其 generation、ID 和磁盘。两者都要求调用方串行化 scope、维持门禁关闭，并持续持有任务直到 SDK 操作结束。启动不会创建替代实例，也不会开放执行或预览入口。

调用方提供 Console 授权的绝对 lease。适配器拒绝过期或缩短的 lease，在任何原生启动之前同步持久化 lease、阶段与 `start_attempted`。source 从 preparing/frozen 进入 rolling_back；已经 committed 的 source 不允许回滚。对停止中的 source，仅当原停止流程记录了宿主进程身份、确认停止，且该进程仍可独立确认已经退出时，才允许启动原磁盘。

启动后核对原生身份、规格与宿主进程生命周期，持久化 `started_process`，再实际执行 Python 和 `/bin/sh` 探测。探测成功后再次核对同一宿主进程、当前操作与有效 lease，才写入 target ready 或 source rolled_back。就绪超时受剩余 lease 限制；SDK 启动本身不使用会丢弃在途操作的超时。超时或异常保留原生实例和意图，不返回成功或触发空白重建。

应答丢失后的重试只可复用同一运行进程，不能更换已记录的宿主生命周期。若 durable 启动意图已经存在，但 SDK 显示 stopped，则拒绝再次启动，保留给后续核对与清理；ready/active/rolled_back 实例停止后也不能靠重复请求自动重启。这样会牺牲部分异常场景的自动恢复，避免将不确定启动误判为尚未启动。

`rolled_back` 在 journal 中代表原实例已恢复就绪；会话管理器仍须接收 Console 的明确激活授权，才可重新开放门禁。源停止前的进程证据和回滚启动后的进程证据分别保留，不能覆盖。跨 Worker 的独立 lease 强制执行、生产启动配置，以及 boot/namespace 变化的启动核对仍需完成，当前不声明生产持久化能力。

## 原生清理与名称保留

`NativeRuntime::finalize_source` 要求当前 source 已记录共享快照提交、完整回读校验和原宿主进程退出证明，才回收源可写根。它不删除已提交归档。`cancel_target` 仅处理尚未激活的目标：先持久化 canceling，再停止并回收目标；迟到的取消不能删除 active 目标。

调用前必须维持对应 scope 门禁关闭、排空执行与预览，并等待所有已开始的 SDK 导入、启动和传输任务实际结束。清理会核对固定原生名称、ID、镜像和完整启动规格，将待删除 ID 及宿主进程身份写入 journal 后才停止实例。SDK 停止成功仍须独立确认该生命周期退出；启动结果不确定、没有进程证据而 SDK 仅显示 stopped 时，保留根和意图，不返回清理成功。清理进程证据、待清理 ID 与名称保留记录只能增加，已确认的记录不能删除或替换。

BoxLite 删除按数据库优先执行，目录删除失败可能只记录日志。适配器因此使用非 force 删除，随后核对原生记录消失，删除同一已记录 ID 的残留目录并 sync 父目录。重启后可根据 durable ID 补齐数据库已删除、物理目录仍存在的清理。拒绝路径穿越、符号链接根、异常权限和不匹配的原生规格；不会用 force 删除向未经核对的 PID 发信号。

回收后，适配器创建一个仅配置、不可启动的原生名称占位：源实例的原名称或 target 的操作/generation 派生名称仍由 SDK 数据库的唯一约束保留。占位不挂载用户磁盘，不拉取镜像，rootfs 指向 `/dev/null` 字符设备之下的不可用路径。其配置绑定 scope、操作、generation 和名称，SDK 配置经过相同的规范化后逐项核对，且不得存在用户根磁盘或宿主 PID。名称保留的 ID 同样持久化；应答丢失可发现相同占位，已确认占位缺失或被替换时拒绝成功应答。

迟到的创建或导入必须遇到已占用名称。若清理期间同一操作名称已有匹配规格的迟到实例，则先记录其 ID、确认停止和退出、清理物理目录，再尝试保留名称。达到重试上限后保留操作等待后续核对。原生适配器覆盖源最终回收、未激活目标取消，以及下述永久 DELETE 的已登记历史清理。生命周期控制器仍负责任务所有权、全局配额、缓存保留、SDK 句柄清理和向 Console 返回最终 ACK，当前 Worker 不声明持久化能力。

原生会话 smoke 额外覆盖共享提交后源回收与重放、名称占位阻止迟到创建、ready 目标实际启动后的取消及退出证明、重开 journal 后清理残留目录、迟到 SDK 导入被名称占位拒绝，以及 active 目标拒绝取消。它仍是本机临时对象服务与测试协调方的验收，不代替真实 Console/S3 或跨机器验收。

## 永久 DELETE 的本地回收

`NativeRuntime::purge_session` 要求 journal 当前操作已是更高 generation 的 delete，Console 已撤销执行权与路由。调用方必须先关闭 scope 的所有入口，排空执行/预览、等待原生与传输任务结束，并释放归档读句柄和缓存 pin。适配器不会在内部采纳一个普通取消请求作为永久删除授权。

清理根据同一账号作用域会话的完整 journal 历史收集旧原生 ID、稳定名称、恢复操作派生名称和进程证据。待回收 ID 与其名称的关联先持久化，旧的不同宿主进程必须已经退出，当前仍运行的实例由原生清理链路记录进程身份、停止并核对退出后回收。SDK 显示 stopped 或记录已不存在，却缺少一个曾启动实例的生命周期证据时，拒绝清理成功。未知启动结果不会被解释为可以安全删盘。

已有名称占位会核对其原操作身份并原样复用，不将占位当成用户实例删除。所有已登记名称继续由 SDK 唯一约束保留；已有占位丢失或被替换时返回冲突，不能悄悄换一个原生 ID。永久删除记录禁止后续更高 generation 再认领此 scope。原生资源回收、名称保留和本地归档回收都成功后，才将操作写为 deleted，保留 journal 供应答丢失与重启后的核对使用。

`Journal::purge_session_artifacts` 仅回收从该 scope 的 source/target 历史计算出的归档、partial、描述临时文件和 UUID 工作目录。它先取得对应下载锁并验证全部待删路径，再删除与 sync 父目录。仍有下载者持锁时返回冲突，不清理其数据；空锁文件保留原 inode，避免迟到等待者与新请求形成两套锁。允许同一已发布文件与其 partial 的双硬链接，拒绝重定向根、异常权限和其他硬链接；目录中的符号链接不被递归跟随。其他 scope 的缓存和原生资源不参与回收。

该链路只处理权威 journal 已登记的本地资源，不操作共享存储对象。Console 的共享对象引用核对和 GC 独立执行。初始化前的归属 Guard 和资源清单已接入原生验收；生产配置、管理帧注册与独立 lease 强制执行已接入；未登记孤儿巡检、boot/namespace 变化的明确协调及完整跨机器验收仍待完成。

原生会话 smoke 覆盖永久删除的完整本地历史回收、删除意图之后完成的 SDK 启动、旧名称占位复用、重复删除、已确认占位丢失时拒绝重建，以及其他 scope 的缓存和原生资源保留。归档回收单测覆盖持锁拒绝、锁 inode 保留、partial 双硬链接、临时文件/工作目录清理和符号链接拒绝。


## 初始化前的 home/journal 归属

原生生命周期验收先取得 [RuntimeHomeGuard](sandbox-snapshot-startup.md)，再调用受保护的 SDK 初始化入口。Guard 绑定目录、Worker、宿主机和 journal，并在 SDK 能够迁移或清理目录前核对原生资源。普通初始化不能绕过已有标记。生产配置、独立 lease、宿主启动上下文变化的自动核对仍需完成；当前不声明生产持久化能力。
