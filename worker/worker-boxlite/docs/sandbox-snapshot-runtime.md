# BoxLite 原生归档与恢复

Worker 固定依赖 BoxLite `0.10.7`，使用原生 `.boxlite` 归档验证同 runtime 的文件系统恢复。当前 Worker 尚未声明 `sandbox_persistence` 能力，也尚未接入 Console 的挂起、上传、恢复、激活和删除协议。

## 原生验收

```bash
cargo run --locked --example boxlite_snapshot_smoke
```

需要可运行 BoxLite 的本机环境、`protoc >= 3.12` 和可访问的镜像 registry。默认镜像使用固定 digest，包含 `/bin/sh` 与 Python。可通过 `BOXLITE_SNAPSHOT_SMOKE_IMAGE` 指定另一个带 digest 的 Debian/Python 镜像；样本会删除 guest 内的 `/etc/debian_version` 以验证基础镜像文件的删除行为。

验收只创建并删除本次调用拥有的临时目录和原生 Box：

1. 子进程在独立 source home 创建并启动 Box，写入文件与元数据样本。
2. 调用 `stop()`，核对状态为 `Stopped`，保留原生实例并导出归档。
3. 源进程使用临时授权向本次测试的 HTTP 对象服务分片上传。父进程校验分片应答并完成对象，再由独立子进程完整 GET 回读与 SHA-256 校验。
4. 父进程删除整个 source home、所有源 journal 和本地源归档，包括源数据库、镜像缓存、backing 文件和 Box 目录。
5. 另一子进程只通过 HTTP 下载共享归档，完整校验后在全新的 target home 规范化并导入，核对导入本身不启动实例、目标原生 ID 与源不同。
6. 显式启动目标，验证文件系统与启动配置，记录示例中的本地激活后再次挂起、导出并校验，最后删除目标和测试目录。失败时保留本次测试目录用于排查。

验收失败会返回非零退出码。输出包含归档字节数、SHA-256、导出和导入耗时。

2026-10-18 在 macOS/arm64 上直接调用 BoxLite 0.10.7 原生 SDK 的小样本结果（不包含平台归档规范化、额外校验和重试）：

| 项目 | 结果 |
| --- | --- |
| 归档大小 | 38,838,232 bytes |
| 导出 | 2,754 ms |
| 导入 | 1,474 ms |
| 普通文件内容、权限、UID/GID | 通过 |
| 硬链接、符号链接、FIFO、user xattr | 通过 |
| 8 MiB 稀疏文件逻辑内容与空洞 | 通过；恢复后占用 8 个 512-byte blocks |
| 基础镜像文件变更与删除 | 通过 |
| 归档内环境变量 | 通过 |
| `/dev/shm` 临时数据不进入恢复 | 通过 |
| 源 home 删除后的新进程、空 home 恢复 | 通过 |

这些是小样本的本机结果，不代表跨机器验收、生产容量、S3 吞吐或 1/5/10 GiB 性能目标。另一个通用 smoke 覆盖并发执行、单执行取消、文件复制与资源删除：`cargo run --locked --example boxlite_smoke`。

原生集成回归包括 detached Box 的正常重启恢复、宿主进程强制退出恢复、guest HTTP tunnel、命令执行和资源清理：

```bash
cargo test --locked --features integration --test integration -- --test-threads=1
```

这组测试运行真实 VM，需要与上述归档验收相同的运行条件。

## 生命周期接入约束

原生 export 会在磁盘复制期间 quiesce，但复制结束会恢复运行中的源实例。平台挂起必须先关闭命令和预览入口、排空执行，再停止所有写入；不能把直接对运行中 Box 调用 `export()` 视为已挂起。当前验收使用停止后的导出，不保留进程或内存。

归档可以在空 home 导入，但目标启动仍需要访问基础镜像 registry。恢复规格必须使用固定平台 digest；不能将可变 tag 的一次成功恢复当作基础镜像一致性的证明。

SDK 的 `BoxArchive::new` 采用可信本地归档策略，会保留归档携带的启动与安全配置。平台适配器必须在导入前核对受控恢复规格、路径和挂载边界、完整 SHA-256、大小及展开预算，再决定导入策略。原生 SDK 的校验不能代替 Console 的账号归属、generation、所有权和激活栅栏。

Console 协议接入还需完成 journal 的运行时接入、连接恢复和执行门禁、直接对象传输与缓存、目标容量预留、激活确认、删除回收，以及 Worker 进程失效后的独立 lease 约束。完成前不向调度器声明此后端支持持久化恢复。


## 持久化 journal

`worker_boxlite::persistence` 提供 BoxLite Worker 的私有恢复规格、归档描述与操作 journal。它是生命周期控制器的存储原语，当前尚未在 Worker 启动、命令执行或恢复握手中启用；journal 测试通过不代表已支持持久化管理 API。

journal 目录使用独立绝对路径，按 Worker identity 绑定。目录及 artifacts 子目录必须属于当前用户且仅当前用户可访问，文件必须为私有普通文件、单硬链接。进程独占锁覆盖 journal 句柄的整个有效期；相同目录不能同时被另一个进程或句柄打开。符号链接、FIFO、异常权限、损坏 JSON、未知字段和超限文件都会拒绝加载。

每次变更先复制并验证完整状态，再写入权限为 `600` 的临时文件，执行文件 sync、原子 rename 和父目录 sync，之后才返回成功。写入出错会禁用该句柄的读取与后续操作；即使 rename 实际已经完成、仅应答丢失，也必须重新打开 journal 核对状态，不能使用旧内存状态继续执行。独立 owner 标记用于识别 journal 丢失，禁止将已有目录自动重置为 generation 1。若整个状态目录被删除，后续启动集成仍需核对原生资源，不能仅凭新目录为空判断不存在旧实例。

操作记录保留账号作用域 session、generation、操作种类和阶段、固定镜像与资源规格、原生 Box ID、归档身份与校验确认。环境变量和启动命令属于私有规格，不实现 `Debug` 输出。传输授权和签名 URL 没有持久化字段，不能作为额外 JSON 字段写入记录。

主要约束：

- 同一操作的重试读取原阶段，不能重新选取归档、规格或原生实例。
- 初始探测固定已有 Box ID；同名替代实例不能被当作原实例采纳。
- source 提交需要归档已校验且远端完整回读已确认；恢复点提交后才能进入源清理完成阶段。
- target 导入需要本地归档已校验，ready/active 必须具有原生 Box ID 与绝对 lease；lease 只能延长。
- 同一 session 的并发 target 认领只能成功一个；取消、终态和 generation 检查限制旧请求的重放。
- 删除记录永久阻止同一稳定 session 的恢复与重建，更高 generation 的未知取消也不能取代删除栅栏。
- 归档文件名由 session、操作与 generation 的摘要生成，不将这些值直接拼接为本地路径。

`cargo test --locked --lib` 覆盖状态机、不可变身份、损坏与私有文件检查、并发认领、真实跨进程锁、子进程被强制结束后的记录恢复，以及写入失败和丢失提交应答的处理。该测试不创建 VM，也不验证对象存储或 Console 协议。


## 原生实例检查与停止写入

`persistence::NativeRuntime` 提供不启动实例的只读检查，以及 journal 约束下的源实例停止原语。Worker 的确定性 session 名称与检查器复用同一个名称生成函数，避免运行路径与持久化路径对实例归属产生不同解释。

检查器要求 BoxLite home 为当前用户拥有、权限为 `700` 的独立绝对路径，不自动修改权限。它按调用方已持有的不可变 Box ID 查找实例，核对账号作用域名称、原生资源与实际镜像解析记录；不按名称寻找替代实例，不从当前 Worker 配置推测已有实例的启动规格。

BoxLite 0.10.7 的公开 `BoxInfo` 不提供完整启动配置。检查器使用只读 SQLite 连接，在同一读取事务内核对 SDK 数据库 schema 10、唯一名称索引与配置 JSON 的一致性，以及该 Box 的不可变 `BoxConfig`。数据库读取有大小上限，不执行迁移或写入；数据库、Box 目录和配置中的 home 不能通过链接跳转到其他位置。SDK 升级必须同步核对该读取契约并运行原生验收。

支持的恢复规格限定为 Libkrun、当前 guest 架构、固定镜像 digest、CPU/内存/进程数，以及可表达的用户、工作目录、环境变量和启动命令。实际镜像 digest 来自原生解析记录，原始可变 tag 不作为恢复身份。其余选项必须匹配 Worker 的已知安全配置；挂载、自定义内核、其他 VMM、自动删除、主机端口、特权模式、自定义宿主隔离配置及未知选项都会拒绝采纳，避免导入时丢失约束或引入宿主依赖。

`stop_source` 要求当前 journal 已认领同一个 source 操作、generation、原生 Box ID 与完整规格。调用方必须先关闭命令/预览入口并排空执行。停止确认前后均检查实例和 journal，停止不确定时保持原记录用于重试；不会删除源实例或创建替代实例。重复停止保持同一个 Box ID。停止后的源磁盘仍应保留到共享归档提交与回读确认完成。

原生归档 smoke 会验证只读检查不停止 VM、未认领及规格不匹配的操作不能停止 VM，以及正确认领后的幂等停止。之后继续执行原生导出和空 home 恢复。这是独立的运行时验收：测试删除 source home 的步骤不表示生产协议可以在共享存储提交前删除源数据。

停止前先读取当前原生实例的私有 `shim.pid`，要求 SDK PID、PID 文件中的启动时间与操作系统观察一致，再把稳定宿主身份、本次宿主启动 UUID、PID namespace、PID 和进程启动时间持久化为不可换绑的 `source_process`。PID 文件缺失、旧格式、损坏、链接或身份冲突都会保留源实例并报错，不把读取失败当作进程不存在。

SDK 在无法附着 live state 时仍可能继续清理并记录停止，因此 `Stopped` 元数据本身不足以确认停止。SDK 停止后还会等待最多 10 秒，独立核对原 shim 已退出，再持久化不可撤销的 `source_stop_confirmed`。原进程仍活着或操作系统证据不可读时不能进入 `frozen`；停止前未记录进程身份的已停止实例也不能直接采纳。进程查询不会发送终止信号或回收其他进程；同宿主重启或 PID 对应的启动时间变化可证明旧生命周期结束，宿主身份不同，或同一次宿主启动内 PID namespace 改变，则拒绝确认，不能把 journal 跨机复制或 PID 不再可见当作原进程已退出。

源操作的冻结、提交和完成记录必须包含停止确认与原进程身份。Worker 在 SDK 已停止、停止确认尚未写入时退出，重开 journal 后仍可用原身份补齐确认，不依赖 SDK 可能已经删除的 PID 文件。已冻结归档重放也要求这项身份记录和退出证据。未确认的停止保留原实例、磁盘和操作记录，由生命周期恢复流程继续核对。

这些原语要求本地 SDK home 与 journal 由同一宿主独占，不共享或复制到另一台宿主运行。Linux 需要宿主唯一且可读的 `/etc/machine-id`、`/proc/sys/kernel/random/boot_id` 、`/proc/self/ns/pid` 及进程启动时间；容器部署须提供正确的宿主身份，不能使用预烘焙的重复 machine-id。macOS 使用 `gethostuuid`、`kern.bootsessionuuid` 和内核进程启动时间。身份读取不可用时停止原语报错。Worker 的持久化能力启用仍需在 SDK 初始化与恢复之前检查宿主、namespace 和本地 home 的归属，独立 lease 强制执行与异常 shim 回收尚未接入。

原生 smoke 验证正常退出的进程证据、SDK 停止后丢失确认的重试，以及无先前进程证据时拒绝采纳停止状态。无 VM 测试使用真实子进程验证 Worker 被 SIGKILL 后仍保留身份、活跃写入者不能确认停止、退出后才能冻结，以及确认不可撤销。它不等同于在真实 SDK 无法附着且 shim 仍活着的分支注入故障。另在 Linux/arm64 的临时 Rust 容器中复用同一进程身份模块源码和固定 SDK 的进程查询实现，7 项进程身份测试通过；容器提供独立的测试 machine-id。这只验证 Linux 内核查询与身份判断分支，不验证 Linux 上的 BoxLite VM 或完整 Worker 生命周期。

这些原语尚未接入 Worker 的管理命令接收与 session 门禁，也不会使 `sandbox_persistence` 声明自动启用。归档处理原语已实现固定镜像、规格、字节上限和完整性校验；后续仍需接入运行中的 Worker，并完成全局磁盘预算、传输协议编排、激活、恢复握手及回收链路。


## 受控导出与归档校验

`NativeRuntime::export_source` 从 journal 中已认领的 source 操作导出。停止前先确认 guest `os.sync()` 成功；刷新失败会保留原实例与操作记录用于核对。导出、压缩和完整校验在阻塞任务中运行。源实例及原始磁盘不会因成功导出或校验失败而删除。

导出先写入按操作标识隔离的私有工作目录，再验证和规范化原生归档。规范化只改变 manifest 与 tar 表达，磁盘逻辑字节及其 SHA-256 保持一致；镜像引用由原始 tag/index 改为已核实的平台 digest。完成后按不可覆盖方式发布归档、sync 父目录，最后将 journal 更新为 `frozen`，记录完整归档 SHA-256、大小和 `verified`。这不等于共享存储已经提交，`remote_verified` 与 `snapshot_committed` 不会由导出设置。

重复请求会完整校验并复用已选归档。若发布文件后、journal 应答前中断，重试会核对同一个私有归档并补齐记录，不能覆盖或重新选择另一组字节。

校验边界：

- 仅接受当前原生 v3 manifest、zstd tar、`manifest.json` 与 `disk.qcow2` 两个成员。
- manifest 不超过 64 KiB，字段与启动规格必须受支持且匹配；未知选项和重复成员会拒绝。
- 路径穿越、额外文件、链接、目录、FIFO、PAX 与长路径扩展会拒绝，不将成员解包到宿主路径。
- GNU 稀疏磁盘支持流式读取；稀疏扩展最多 1024 个头，预检发生在 tar 逻辑读取器分配块表之前。
- QCOW2 必须为支持的独立磁盘头格式，不允许 backing 引用、外部数据文件、加密或不兼容标记；同时检查完整磁盘 checksum。
- 原始归档、规范化输出和传入的恢复归档均有字节上限，并核对完整归档 SHA-256。输入与输出不能是同一个 inode。
- 展开预算保守计入 QCOW2 文件逻辑长度、虚拟容量及 64 KiB manifest 余量；压缩大小不能代替这个预算。

`prepare_import_archive` 先验证已提交归档的描述、完整 SHA-256、账号作用域与恢复规格，再生成本机私有导入归档。归档只可携带已知 Linux/macOS 默认宿主安全配置，导入前统一重建为当前机器的默认隔离与受控资源限制。调用 SDK 的可信本地导入策略之前必须完成这一步，不能直接沿用源机器的宿主配置。

SDK 不会为导入实例补齐 `resolved_image`。`inspect_target` 因此要求 journal 中存在当前 target 操作、已验证归档、已选择的不可变 Box ID 和固定规格，并核对原生配置中的完整 digest 与该规格一致。普通源实例采纳仍要求原生镜像解析记录，不能使用这条导入专用路径采纳任意已有实例。

当前 `cargo run --locked --example boxlite_snapshot_smoke` 覆盖规范化导出、冻结记录重试、发布后未收到 journal 完成应答的恢复、预算拒绝后源数据保留，以及删除源 home 和源 journal 后的目标导入与完整规格核对。样本代码写入文件后不自行执行 sync，由停止原语负责刷新。目标恢复仍验证内容、链接、权限、UID/GID、FIFO、xattr、稀疏文件、基础镜像文件删除、环境变量和 tmpfs 排除。

这条校验流程比裸 SDK 增加完整读取与压缩。一次 debug 构建的小样本中，含冻结归档重放校验的源流程约 25 秒，目标规范化与导入约 24 秒，归档约 38.8 MB、展开预算约 924.5 MB；这些时间不是 release 性能或容量验收结果，也不包括共享对象传输。1/5/10 GiB 和并发性能验收仍需单独完成。

生命周期控制器仍需在调用前预留 SDK home 与 journal artifacts 两处空间，管理在途任务、缓存和临时文件。SDK 原始导出使用其原生暂存机制，原始归档大小在导出完成后检查；这里的限制不能代替文件系统配额或节点级磁盘准入。取消时必须跟踪并等待 SDK 已启动的原生 I/O，不能仅丢弃 Future 就释放占用。崩溃遗留工作目录和 SDK 临时文件的巡检回收仍待接入。

原生导入使用下述 journal 约束的导入原语；删除栅栏、实例/路由激活与运行中 Worker 的恢复握手仍需控制器落实。

已导入实例再次挂起时，`inspect_source` 会要求同一 scope、generation、Box ID 与完整规格对应的已激活 target 记录，才能使用导入时固定的镜像身份。原生验收覆盖导入、记录本地激活后再次导出；它仍不验证 Console 激活事务。journal 回收必须保留当前原生实例依赖的这条导入证据，不能把它作为无引用历史记录删除。


## 受控导入与实例身份

`NativeRuntime::import_target` 从当前 target 操作及其固定 artifact 读取已下载归档，完整核对 SHA-256、范围、规格与展开预算，并生成当前主机安全配置下的私有导入归档。SDK 导入前先持久化 `verified` 与 `importing`，导入后验证停止状态和完整规格，再持久化不可变 Box ID。该原语不会启动实例或开放命令/预览入口。调用方须先预留 SDK home 与 journal 两处暂存空间、按 session 串行执行，并在取消后继续跟踪 SDK I/O 至结束。

普通新建会话沿用 `onlyboxes-terminal-v1-<scope 摘要>` 名称。恢复实例使用 `onlyboxes-restore-v1-<scope、operation、generation 元组摘要>`；SDK 数据库的名称唯一约束使不同恢复代次拥有独立名称。名称不包含账号、session 或操作的明文。Worker 管理器后续必须使用已记录的原生 ID 绑定恢复实例，不能通过普通创建路径重新寻找稳定名称。

若 SDK 已导入但 journal 尚未记下原生 ID，重试仅检查本次操作的完整派生名称，要求实例仍停止、完整启动配置一致，且本机独立 `disk.qcow2` 的逻辑长度与完整 SHA-256 均等于已验证归档中的磁盘。随后才能将该 ID 固定到当前操作。运行中的未知候选、其他代次名称、内容改变的磁盘或配置冲突都会拒绝采纳；不以名称与镜像相同作为充分依据，不创建空白替代实例。

已有 Box ID 后，重试按同一个 ID 核对，实例缺失会报告缺失，不能重新导入并换 ID。若该实例已经运行，还要求 journal 中的绝对 lease 尚未过期；导入原语不续期，也不替代独立 lease 强制执行。后续控制器仍须在启动之前持久化 lease，待环境就绪后保持入口关闭，完成 Console 所有权提交与激活握手。

恢复实例再次挂起时，检查器从同一 generation、Box ID 与规格的已激活 target 记录取得原生操作名称。导出先核对实际名称，再把归档 manifest 规范化为稳定的 scope 名称；下一次恢复不依赖前一 Worker 的操作名称或本机 ID。归档磁盘字节不因名称规范化而改变。

原生 smoke 覆盖旧稳定名称仍存在时的新导入、同 journal 重试，以及根据重建的导入中间记录找回同一个停止实例。预算不足、取消、删除记录取代旧操作及错误 generation 均不能创建或采纳目标；已选原生实例被移除后，重试报告缺失，不会创建替代实例。重建记录模拟“SDK 已完成、原生 ID 应答未记入 journal”的状态，不等同于在 SDK 导入任意指令处执行强制退出。名称隔离、原生磁盘完整性及链接拒绝另有无 VM 测试。示例的 `import_ms` 计入下载、归档规范化、磁盘核对和应答丢失重放，不是单次裸 SDK 导入延迟。删除永久栅栏、迟到导入回收与 Worker 启动恢复仍需接入。


## 直接对象传输

`persistence::Transfer` 使用仅存在内存中的 `TransferGrant`，支持上传分片、完成对象后的完整 GET 回读、断点下载与已验证的本机归档复用。授权 URL 和 headers 不写入 journal、下载标记或公开错误；续期和分片完成仍由 Console 协议编排，Worker 不持有 S3 主凭据。

传输与阻塞文件 I/O 分别共享 1–16 个并发配额。流式读写以 64 KiB 块处理，上传按固定 FD 的独立偏移读取，先完整校验 SHA-256，再核对每批上传前后的 inode、长度和修改时间。单批最多 16 个分片，重复编号、重叠范围和越界范围在发起请求前拒绝。分片应答要求 HTTP 200 和 ETag；ETag 不能代替最终完整 GET 的大小与 SHA-256 校验。

授权过期、主动取消、连接失败或 1–600 秒无进度超时会终止请求；超时覆盖等待响应头、传输正文与等待上传确认。等待并发配额时同样检查授权过期和取消。禁止 HTTP 重定向和透明内容解压，校验授权 method、Host、Content-Length 和 headers，不透传远端错误正文。已经启动的阻塞 I/O 在实际返回前继续占用文件配额；取消 Future 不会提前释放这项配额。

下载目标必须位于当前用户拥有的私有目录。每个目标使用跨进程排他锁，`.partial.json` 只持久化固定归档描述，`.partial` 不能被另一 snapshot 继续使用。短读、网络失败或取消保留私有前缀；重试的 HTTP 206 必须精确匹配剩余 Content-Range，服务端返回完整 HTTP 200 时从零开始。错误范围、长度或完整 checksum 会丢弃本次对应的临时文件。完整校验和文件 sync 完成后才能通过不可覆盖的 hard link 发布，并 sync 父目录；发布后丢失应答可以根据同 inode 恢复。已发布缓存每次复用都完整核对大小和 SHA-256，损坏缓存由调用方决定清理，不直接覆盖。

原生 smoke 使用临时 HTTP 对象服务验证“导出 → 分片上传 → 协调方完成对象 → 完整回读 → 删除源状态 → HTTP 下载 → 空 home 导入 → 再次挂起”。该服务使用测试授权，不实现 S3 签名、版本控制、条件 manifest 写入或 Console 事务，不能作为真实 S3 兼容性或跨机器验收。传输故障测试覆盖中断续传、取消、响应头/正文停滞、授权过期、错误范围、checksum 失败、重定向、文件替换、发布应答丢失和阻塞 I/O 配额保持。

这些是传输原语。Worker 的持久化能力声明、Console 授权续期与回读确认、缓存配额及回收仍需生命周期控制器接入。
