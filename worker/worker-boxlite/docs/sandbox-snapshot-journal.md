# BoxLite journal 规格共享编码

BoxLite 的私有 journal 使用磁盘格式 v2，将恢复规格按 SHA-256 共享存储。多轮快照与恢复产生的操作可引用同一规格，完整环境变量和启动命令只写入一次。操作、scope、generation、阶段、原生 Box ID、归档描述、进程身份、启动授权、名称占位和租约回收回执仍逐项保留。

该编码覆盖运行、挂起、已删除及未决操作中的重复规格，不以阶段变化推断原生资源已经回收，不移除历史记录或改变恢复、删除与所有权判定。跨操作的回收凭据关联保持完整。它减少重复配置的磁盘写入，不提供无限历史或常数空间保证。

## 磁盘编码与逻辑视图

磁盘文件继续使用原有 `journal.json`、私有目录、独占锁和原子同步写入流程：

- 顶层 `version` 为 `2`，`restore_specs` 将摘要映射到完整私有规格。
- 每条需要规格的操作保留原有字段和层次，以 `restore_spec_sha256` 引用表内规格；不内联 `restore_spec`。
- 空取消记录不需要规格。规格表只包含当前文件中确实被操作引用的条目。
- 摘要计算对象为 `RestoreSpec` 的规范化 serde JSON 字节：固定结构字段顺序、规范化数值和按键排序的环境变量。格式变更必须保留该约定或另行升级版本。

`Journal::open` 和 `JournalState` 的 serde 读取入口先校验编码、摘要、引用与展开预算，再恢复完整的规格。`Journal::snapshot` 及原生预检、恢复、删除、缓存逻辑获得原有完整逻辑视图，规格引用字段被清空；逻辑视图的 `version=1` 和完整序列化形式不等同于磁盘 v2 编码。运行时 claim/update 不接受携带 `restore_spec_sha256` 的操作，摘要本身不能授予启动或清理权限。

公开 API、registry 协议、快照归档格式、配置以及 home/Worker/lease-store 的配对身份均不改变。归档中携带的恢复规格与 journal 的私有引用编码相互独立。

`initial_creations` 另记录 SDK 创建前的初始会话意图及不可替换的选定原生 ID，随 v2 编码完整保留，不放入恢复规格共享表，也不因创建结果未知而丢弃。其选项摘要、创建者、守护器、scope、期限及 boot 关联的约束见[初始创建意图](sandbox-snapshot-startup.md#初始创建意图)。只保存该摘要不能授予启动、采纳或删除权限；未完成意图在 SDK 初始化前拒绝开放。

## 读取、升级与失败

Worker 可读取完整规格形式的 v1 和共享规格形式的 v2。只读重开 v1 不重写文件；下一次成功持久化变更写入 v2。新 journal 从首次持久化起使用 v2。旧 Worker 不能打开 v2，升级后不能直接降级使用旧二进制；禁止通过删除 journal、改写版本号或更换 owner 标记绕过检查。

v2 的缺失引用、摘要不匹配、内联规格与引用混用、未被引用的表项、无规格操作非法引用规格，以及不一致的操作/代际/清理凭据都会拒绝加载。未知字段、异常权限、链接、损坏文件和目录配对检查继续生效。失败保留原文件，不回退到空状态。

文件大小上限仍为 64 MiB。编码与解码还对下列保守展开预算应用同一 64 MiB 上限：

```text
v2 完整编码大小 + 所有操作所引用规格的编码大小之和
```

共享规格每被引用一次就计入一次展开成本。解码在复制规格之前核对该预算，避免很小的磁盘文件展开为无界内存；编码在创建临时文件之前使用相同预算，保证成功写入的编码能重新打开。预算通过计数序列化核对，不额外创建一份完整展开 JSON。该预算是逻辑编码的上界，不是 Worker 堆内存或原生磁盘的硬配额，达到限制仍保持不可用并保留所有权。

成功提交仍要求临时文件写入与 sync、原子 rename、父目录 sync。写失败禁用当前句柄，重开后核对实际提交结果。升级失败发生在替换之前时保留 v1；若 v2 已实际替换但应答丢失，重开会读取同一操作、阶段和规格的 v2。不得继续使用旧内存状态决策。

## 验证与边界

```bash
cargo test --locked codec_tests -- --nocapture
cargo test --locked creation_tests
cargo test --locked
cargo build --locked --bin boxlite-lease-guard
cargo run --locked --example boxlite_lifecycle_controls_smoke
```

共享规格测试包含 120 条重复 16 KiB 环境配置的准备记录，以及已完成源、准备目标、运行采纳、永久删除和不同规格的记录。完整逻辑序列化为 2,167,755 bytes，磁盘 v2 为 112,233 bytes；重开后完整逻辑序列化逐字节一致。该数字是元数据样例，不是归档吞吐或生产性能保证。

失败注入覆盖升级替换前失败、替换后的应答丢失、引用/摘要/表项异常，以及 5,000 条引用形成的超限展开。超限写入关闭准入且不替换已有文件；超限读取在复制共享规格前拒绝，保留原始字节。运行时非法引用不能通过 claim/update。

创建意图测试覆盖 ID 未知时落盘和重开、空 SDK home 仍拒绝开放、同一意图重放、选定 ID 不可替换、跨 scope ID/operation 冒用拒绝、boot 精确关联和损坏关联的加载拒绝。另核对 SDK 选项规范化的幂等性、配置 JSON 往返及超限编码拒绝；原生清单直接核对保存的选项，内存或 SDK 派生文件写入上限发生变化均拒绝，不能再次规范化后隐藏变化。正常创建、跨 Worker 生命周期及已确认初始根的离线到期回收另有[真实服务回归](sandbox-snapshot-initial-creation-sample-2026-10-25.json)。

原生生命周期验收通过初始采纳、回滚、管理器重建、分片传输、回读确认、同节点缓存恢复、损坏缓存回源、守护器重开后的回收回执、普通执行/续租/资源读取和永久删除重放，退出后的原生清单继续接受 journal 中固定的名称占位。

已有本机 Worker 目录与身份也已通过真实 Console/S3 的 `--runtime boxlite --return-to-source` 循环，磁盘文件确认使用 v2 且所有操作引用均有对应规格。跨 Worker、同 Worker、无 Worker 后恢复、有效旧缓存存在时使用最新快照、文件增删改保留和最终零清理积压均通过。Worker 离线时，其清理任务继续保留；同一归属重新上线后继续原任务，不能把逻辑删除回执或启动指令已提交当作物理清理完成。

所有历史操作及清理凭据仍保留，已删除会话的私有规格仍可能作为共享条目存在。原生回执和历史记录的进一步退休/压缩、未登记孤儿协调及跨物理机器验收仍是独立工作。该编码不代替[周期缓存清扫](sandbox-snapshot-control.md#同节点归档缓存)或原生磁盘清理。
